Step 0: Setup
Make the folders from the structure.
Write a basic Makefile with $(NAME), all, clean, fclean, re. Use cc -Wall -Wextra -Werror.
Make push_swap.h with the include guard and #include <stdlib.h>, <unistd.h>.
Test: make works, and a second make does nothing.
Step 1: push_swap.h (the data)

You need three types. Draw them first.

t_node   → value, next arrow
t_stack  → head (first node), size
t_data   → stack a, stack b, move counters, bench flag

Passing one t_data pointer to every function replaces global variables and keeps parameters under 4.

Test: the header compiles when you include it in an empty .c file.
Step 2: stack/stack_utils.c

Job: the linked list tools.

Function	What it does
new_node	makes a node (you did this)
add_front	puts a node at the top
add_back	puts a node at the bottom
remove_front	takes the top node out and gives it back
free_stack	frees every node

The Norm allows 5 functions per file. Put stack_size and last_node in a second file (stack_utils2.c).

Test: add 3 numbers, print, remove one, free. valgrind is clean. Test an empty list.
Step 3: the moves

Four files, one idea each. Each move works on t_data.

moves/push.c: pa, pb

Take the top of one stack. Put it on top of the other.
Do nothing if the source is empty.

moves/swap.c: sa, sb, ss

Swap the top two nodes. Do nothing if there are fewer than 2.

moves/rotate.c: ra, rb, rr

The first node goes to the end.

moves/reverse_rotate.c: rra, rrb, rrr

The last node goes to the front. (This is the hard one. See the single vs doubly list talk.)

Every move must also: print its name and a new line, and add 1 to its counter.

ss, rr and rrr count as one move. Decide how you print and count them. Don’t call sa and sb and count two.

Test: build a = 1 2 3. Do ra, then rra. You must get 1 2 3 back. Do every move and compare with the pictures. Check an empty stack and a one-node stack.
Step 4: parsing (three files)

parse/parse_checks.c (small checks)

Is this text a valid number? (optional sign, then at least one digit, then only digits)
Does it fit in an int?
Is it a duplicate?

parse/parse_flags.c

Is this argument a flag? Which one?
Save the choice in t_data. Only the first argument(s) may be flags. Decide your rule.

parse/parse_args.c

Go through the arguments. Build stack a. The first number is the top.
On any error: free what you made, print Error to stderr, stop.
Test: 0 one 2 3, 3 2 3, 99999999999, -, +5, -2147483648, 2147483647, no arguments. Compare with the subject examples. valgrind after errors too.
Step 5: main.c (first version)

Job: call things in order. Almost no logic.

Order: parse, then (later) disorder, strategy, algorithm, bench, free.

Test: ./push_swap 3 1 2 builds the stack and exits. Add a temporary print to see the stack.
Step 6: metrics/disorder.c

Job: count the pairs where a bigger number comes before a smaller one, then divide by the total pairs. Do it before any move.

Watch out: the answer is a fraction. Plain integer division gives 0.
Test: sorted gives 0, reversed gives 1, 2 1 3 gives about 0.33. Check 1 number (no pairs): do not divide by 0.
Step 7: stack/stack_index.c

Job: replace each number by its rank (smallest becomes 0, next 1...). Radix needs this, and it also helps the medium algorithm.

Test: -5 100 3 becomes 0 2 1.
Step 8: algos/small_sort.c

Job: fixed solutions for 2 and 3 numbers, and then 5.

Sort 3: only a few cases. Solve all 6 orders on paper first.
Test: every order of 2, 3, 5 numbers sorts. Count the moves.
Step 9: algos/simple.c (O(n²))

Job: one simple idea. For example: push the smallest to b again and again, then push all back.

Trace on 5 numbers by hand first.
Test: 10, 100, 500 random numbers. A checker says OK. Write down the move count.
Step 10: algos/medium.c (O(n√n))

Job: chunks. Split the ranks into about √n groups. Push group by group to b, then bring back the biggest first.

Draw 10 numbers in 3 chunks on paper first.
Test: OK, and fewer moves than simple.c for 100 numbers.
Step 11: algos/complex.c (O(n log n))

Job: a common choice is radix sort on the ranks. Each pass looks at one bit.

Trace on 5 numbers by hand first.
Test: OK. Goals: 100 numbers under 700 (excellent), 500 under 5500.
Step 12: algos/adaptive.c

Job: pick a method from the disorder.

below 0.2: the O(n²) method,
0.2 up to 0.5: the O(n√n) method,
0.5 or more: the O(n log n) method.

Write down why you chose those limits for the README.

Test: build inputs for each range. Check the right method runs, and every result is sorted.
Step 13: flags and metrics/bench.c

Job:

--simple, --medium, --complex, --adaptive choose the strategy. No flag means adaptive.
--bench prints to stderr: disorder (as a % with 2 decimals), strategy name and class, total moves, and the count of each move.
Test: the subject examples. 2> bench.txt must leave stdout clean. Without --bench, nothing appears on stderr.
